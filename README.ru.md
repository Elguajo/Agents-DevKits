## Что это за проект

Архитектурное направление проекта — **система ИИ-процессов разработки ПО**: мы в первую очередь создаём не самих агентов, а систему, через которую ИИ-агенты разрабатывают программное обеспечение.

Это означает координацию:

```text
замысел проекта
    ↓
обнаружение / маршрутизация навыков
    ↓
специализированные процессы
    ↓
инструменты и интеграции
    ↓
реализация
    ↓
проверка и ревью
    ↓
доказательства готовности к выпуску
    ↓
РЕЛИЗ
```

Поэтому навыки — лишь один из слоёв системы, а не вся система целиком.

Цель — сделать разработку ПО с помощью ИИ более осознанной, повторно используемой, проверяемой, устойчивой к конфликтам и готовой к продакшену, не навязывая излишний процесс простым задачам.

Полное описание концепции и план развития приведены в [`docs/ai-development-workflow-system.md`](docs/ai-development-workflow-system.md).

## Зачем существует этот репозиторий

Полезные ИИ-процессы разработки должны быть повторно используемыми, проверяемыми, переносимыми и чётко ограниченными, а не скрытыми в чате или вручную скопированными между компьютерами.

Этот репозиторий — единый источник правды для системы процессов и переносимого слоя машины разработчика: навыков, метаданных маршрутизации, границ ответственности, происхождения, логики установки, безопасного baseline Codex и документации.

Каждый навык соответствует формату [Agent Skills](https://agentskills.io/): каталог с `SKILL.md`, а также необязательными скриптами, справочными материалами и ресурсами. Сейчас репозиторий поддерживает установку в Codex Desktop и Claude Code; другой агент сможет использовать этот формат только при наличии совместимого механизма обнаружения навыков.

Система намеренно учитывает **конфликты**. Каждый специалист владеет одной основной областью и передаёт работу дальше, а не конкурирует с соседними навыками. См. [`docs/skill-boundaries.md`](docs/skill-boundaries.md).

Подробное объяснение навыков, агентов, инструментов, MCP, субагентов, хуков, разрешений, памяти, плагинов и автоматизаций приведено в [`docs/agent-architecture.md`](docs/agent-architecture.md).

## Быстрый старт

Требования: Git и оболочка, совместимая с Bash. Клонируйте репозиторий на новом компьютере и выполните одну команду из его корня:

```bash
git clone https://github.com/Elguajo/Agents-DevKits.git
cd Agents-DevKits
./bootstrap.sh
```

После установки храните этот клон в постоянном месте. Установщик создаёт абсолютные символические ссылки на него, поэтому перенос или удаление репозитория сломает установленные навыки.

В Windows выполняйте команды из Git Bash. Для создания символических ссылок также может потребоваться включить режим разработчика или использовать оболочку с повышенными правами.

`bootstrap.sh` проверяет наличие навыков, затем подключает каждый из них к обоим локальным агентам:

| Агент | Локальное расположение навыков |
|---|---|
| Codex Desktop | `~/.codex/skills/<skill-name>` |
| Claude Code | `~/.claude/skills/<skill-name>` |

Существующие навыки никогда не перезаписываются. Чтобы намеренно заменить существующую локальную копию, используйте:

```bash
./bootstrap.sh --adopt
```

Предыдущая копия перемещается в `~/.agent-skills-backups/`; ничего не удаляется. Установщик также удаляет только неработающие символические ссылки, которыми ранее управлял этот репозиторий, поэтому переименование управляемого навыка не затрагивает несвязанные локальные навыки.

Перезапустите Codex или Claude Code, если один из них уже работал во время установки новых навыков.

### Попросить ИИ-агента настроить систему

После клонирования репозитория вставьте один из этих промптов в Codex или
Claude Code.

**Только skills — безопасный вариант по умолчанию**

~~~text
Установи только skills Agents DevKits из этого репозитория. Запусти
./bootstrap.sh из корня репозитория. Не используй --adopt: сохрани все
существующие локальные skills, затем сообщи, какие skills были подключены или
пропущены.
~~~

**Полный шаблон машины macOS/Codex**

~~~text
Настрой эту macOS-машину по шаблону Agents DevKits. Сначала запусти
./devkit.sh doctor, затем ./devkit.sh bootstrap --profile base --profile web
--profile ai. Сохрани текущую конфигурацию Codex через adoption flow Devkit, не
включай MCP-профили, пока я не назову их, и отчитайся о каждом системном
изменении.
~~~

Полный шаблон устанавливает Homebrew-пакеты и может менять глобальные настройки
Git, shell и macOS. Перед подтверждением прочитайте предложенные действия.

## Devkit для машины разработчика

Необязательный слой devkit/ настраивает macOS-машину и управляет локальной
конфигурацией Codex. Он независим от установки навыков — используйте только
нужную часть.

На новом Mac:

~~~bash
./devkit.sh bootstrap --profile base --profile web --profile ai
~~~

На уже настроенном Mac сначала примите текущую конфигурацию Codex:

~~~bash
./devkit.sh backup
./devkit.sh install
~~~

install не перезаписывает существующий config Codex без игнорируемого
host-local override. MCP включаются только явно:

~~~bash
./devkit.sh mcp list
./devkit.sh mcp enable playwright context7
./devkit.sh mcp doctor
~~~

Все команды, профили, границы приватности и portable export описаны в
[devkit/README.md](devkit/README.md).

### Начало работы с навыками

После перезапуска агента опишите задачу обычным языком или явно укажите навык, если нужен конкретный процесс. Например:

```text
Используй product-spec, чтобы превратить идею функции в критерии приёмки.
Используй feature-development, чтобы реализовать эту функцию с привлечением подходящих специалистов.
```

Чтобы выбрать навык явно, откройте [`SKILLS.md`](SKILLS.md); либо позвольте агенту с маршрутизацией навыков выбрать его по задаче. Каждый установленный `SKILL.md` содержит обязательные для выполнения инструкции.

### Проверка или отмена установки

Установщик создаёт ссылки для **обоих** Codex Desktop и Claude Code, даже если сейчас установлен только один из них. Проверить отдельную ссылку и её цель можно так:

```bash
readlink "$HOME/.codex/skills/product-spec"
readlink "$HOME/.claude/skills/product-spec"
```

Чтобы перестать управлять одним навыком, удалите только его символическую ссылку: `unlink "$HOME/.codex/skills/<skill-name>"` или `unlink "$HOME/.claude/skills/<skill-name>"`. Если навык был заменён с `--adopt`, сначала удалите его символическую ссылку, затем восстановите исходный каталог из пути с временной меткой в `~/.agent-skills-backups/`. Установщик никогда не удаляет принятый каталог.

### Обновление навыков

Обновите локальные ссылки после изменения репозитория:

```bash
./bootstrap.sh
```

Получите и установите последнюю версию библиотеки:

```bash
git pull --ff-only
./bootstrap.sh
```

После переименования управляемого репозиторием навыка та же команда удалит его устаревшую неработающую управляемую ссылку и создаст новую.

## Project runtime

Необязательный project runtime описывает, какие глобально установленные навыки,
агентные цели, переносимые capability и проверки самого репозитория относятся к
одному проекту. Это тонкий слой копируемых шаблонов: он не создаёт копии skills
в `.agents/skills` или `.claude/skills`, не делает project-симлинки и не хранит
историю запусков.

Из checkout этой библиотеки инициализируйте уже существующий каталог проекта:

```bash
python3 project.py init --path ../my-project
python3 project.py doctor --path ../my-project
```

По умолчанию создаются Codex `AGENTS.md`, Claude Code `CLAUDE.md` и
версионируемый `agents-devkits.yaml`. Существующие instruction-файлы не
перезаписываются: для них создаётся integration snippet; `--adopt` сперва
сохраняет backup с временной меткой, затем добавляет управляемый блок. Проверки
запускаются только явной командой:

```bash
python3 project.py verify --path ../my-project
python3 project.py verify --path ../my-project --changed src/ui/button.tsx --json
```

`project.sh` остаётся compatibility wrapper. Полная схема manifest, границы
безопасности и команды описаны в
[`docs/project-runtime.md`](docs/project-runtime.md).

## Карта процесса

Это текущая модель процесса разработки ПО. **Не обязательно запускать каждый навык для каждой задачи.** `feature-development` выступает оркестратором и должен выбирать только тех специалистов, которых оправдывает изменение.

```text
                                  ПРОДУКТ
                                     │
                                     ▼
                             ┌──────────────┐
                             │ product-spec │
                             └──────┬───────┘
                                    │
                                    ▼
                           codebase-explorer
                                    │
                                    ▼
                         solution-architecture
                                    │
                                    ▼
                         feature-development
                           (оркестрация)
                                    │
                    ┌───────────────┴───────────────┐
                    │                               │
                    ▼                               ▼
                ФРОНТЕНД                          БЭКЕНД
                    │                               │
         ┌──────────┼──────────┐                    │
         │          │          │                    │
         ▼          ▼          ▼                    │
  frontend-design   │      figma-to-code            │
                    │                               │
             design-system                          │
                    │                               │
            responsive-design                       │
                    │                               │
              motion-design                         │
                    │                               │
                    └───────────────┬───────────────┘
                                    │
                                    ▼
                              РЕАЛИЗАЦИЯ
                                    │
                         debugging / refactor
                                    │
                                    ▼
                                  ТЕСТЫ
                         ┌──────────┴──────────┐
                         │                     │
                         ▼                     ▼
                      testing        playwright-testing
                                               │
                                               ▼
                                           visual-qa
                                    │
                    ┌───────────────┼────────────────┐
                    │               │                │
                    ▼               ▼                ▼
          accessibility-review  performance-review  code-review
                                                     │
                                                     ▼
                                               security-review
                                                     │
                                                     ▼
                                                release-check
                                                     │
                                                     ▼
                                                   РЕЛИЗ
```

Карту точнее читать так:

- **Определение:** что должно существовать?
- **Понимание:** как работает текущая система?
- **Архитектура:** как изменение должно в неё встроиться?
- **Специалисты реализации:** какие дисциплинарные процессы применимы?
- **Проверка:** работает ли результат и выглядит ли он правильно?
- **Ревью:** поддерживаемо, безопасно, доступно и производительно ли решение там, где это нужно?
- **Контроль выпуска:** достаточно ли доказательств для релиза?

Долгосрочное направление добавляет интеллектуальную маршрутизацию, выполнение с учётом инструментов, завершение с учётом доказательств и повторно используемую загрузку проектов. См. [план развития AI Development Workflow System](docs/ai-development-workflow-system.md#development-direction).

## Включённые навыки

Библиотека навыков охватывает определение продукта, исследование кодовой базы, архитектуру, оркестрацию функций, фронтенд-реализацию, отладку, тестирование, QA, ревью, проверки перед выпуском и одну утилиту атрибуции GitHub.

Для выбора навыка используйте [`SKILLS.md`](SKILLS.md): это полный человекочитаемый каталог, включающий зоны ответственности, условия запуска, происхождение и передачу работы. Для машиночитаемых метаданных маршрутизации используйте [`skills/registry.yaml`](skills/registry.yaml). Каждый `skills/<skill>/SKILL.md` является источником истины для инструкций по выполнению.

Все перечисленные навыки предназначены для Codex и Claude Code, если только в документации навыка явно не указана зависимость от конкретного агента.

## Как навыки избегают конфликтов

Ключевое правило: **одна основная область ответственности на одну задачу**.

- `codebase-explorer` объясняет, **как репозиторий работает сейчас**; `solution-architecture` определяет, **как он должен измениться**.
- `product-spec` отвечает за продуктовый замысел и критерии приёмки; `solution-architecture` — за техническую структуру.
- `frontend-design` отвечает за художественное направление; `design-system` — за согласованность с существующей системой.
- Предоставленный Figma-макет или иной референс имеет приоритет над эстетической переинтерпретацией; `figma-to-code` следует источнику истины.
- `responsive-design` определяет адаптивное поведение; `visual-qa` проверяет отрисованный результат.
- `testing` отвечает за регрессионное unit/integration-покрытие; `playwright-testing` — за браузерное E2E-поведение.
- `debugging` меняет поведение для исправления дефекта; `refactor` сохраняет поведение.
- `code-review` отвечает за общее качество изменений; `security-review` — за анализ с фокусом на угрозы.
- `release-check` проверяет доказательства; он не повторяет архитектурную, дизайнерскую работу или реализацию.

Полные правила приоритета и разрешения коллизий: [`docs/skill-boundaries.md`](docs/skill-boundaries.md).

## Как это работает

```text
Agents-DevKits/skills/<skill>/SKILL.md
                 │
                 ├── ~/.codex/skills/<skill>   → Codex
                 └── ~/.claude/skills/<skill>  → Claude Code
```

Установщик создаёт абсолютные символические ссылки, поэтому обновление, закоммиченное в этот репозиторий, становится канонической локальной версией для обоих агентов после локального обновления репозитория.

Не переносите и не удаляйте клон, пока хотите пользоваться установленными навыками. Если его нужно переместить, сначала удалите существующие символические ссылки навыков, затем запустите `./bootstrap.sh` из нового расположения.

## Использование и принятие навыков

| Ситуация | Команда | Результат |
|---|---|---|
| Новый компьютер или нет конфликтующего локального навыка | `./bootstrap.sh` | Добавляет недостающие ссылки и оставляет нетронутыми все существующие несвязанные локальные навыки. |
| Существующим локальным навыком должен управлять этот репозиторий | `./bootstrap.sh --adopt` | Перемещает существующий каталог в резервную копию с временной меткой, затем заменяет его ссылкой на этот репозиторий. |

Используйте `--adopt` только если версия в репозитории — та, которую вы хотите использовать в обоих агентах. Предыдущие локальные каталоги остаются доступными для восстановления в `~/.agent-skills-backups/`.

Навыки можно выбрать по формулировке запроса или вызвать явно, когда подходит несколько навыков. Инструкции проекта и явные требования пользователя всегда имеют приоритет над общими указаниями навыков.

Установщик выводит точную сводку по новым, уже существующим, пропущенным, сохранённым и удалённым устаревшим ссылкам навыков. Пропущенный навык остаётся нетронутым; используйте `--adopt`, только когда действительно намерены его заменить.

## Добавление навыка

По умолчанию создавайте навык только из инструкций. Добавляйте скрипты лишь тогда, когда они устраняют повторяющуюся и подверженную ошибкам работу.

```text
skills/
└── my-skill/
    └── SKILL.md
```

Перед коммитом нового навыка убедитесь, что:

1. В `description` указаны понятные пользовательские условия запуска.
2. Его ответственность не дублирует существующий навык.
3. При возможном пересечении явно заданы правила `Use when` / `Do not use when` / передачи работы.
4. Процесс работает в обоих агентах или явно объясняет, почему зависит от конкретного агента.
5. Включённые скрипты имеют минимум зависимостей, пригодны для ревью и протестированы.
6. Импортированные навыки сохраняют исходную лицензию и сведения о происхождении.
7. Новый навык добавлен и в [`SKILLS.md`](SKILLS.md), и в [`skills/registry.yaml`](skills/registry.yaml).

Затем установите его локально:

```bash
./bootstrap.sh
```

## Безопасность и происхождение

- `bootstrap.sh` создаёт ссылки и удаляет только устаревшие неработающие символические ссылки, которыми ранее управлял этот репозиторий. Он не устанавливает пакеты, не меняет глобальные настройки Git и не запускает вложенные скрипты навыков.
- Git не запускает установщик автоматически при `clone`; установка — осознанное локальное действие.
- Проверяйте сторонние инструкции и скрипты перед их добавлением. Не храните в репозитории ключи API провайдеров, токены и приватный контекст.
- Импортированные навыки содержат свою лицензию и `SOURCE.md` с точной версией исходного кода. `frontend-design` сохраняет данные о происхождении и лицензионные файлы исходного проекта.

## Структура репозитория

Рассматривайте этот раздел как **карту навигации для людей и агентов**. Дерево файлов показывает, где находится информация; таблица ниже объясняет, к какому источнику обращаться с каждым вопросом.

Предполагаемый порядок чтения:

```text
README.md / Структура репозитория
            │
            ├── Понять систему ───────────────────→ ai-development-workflow-system.md
            │
            ├── Человеку выбрать навык ───────────→ SKILLS.md
            │                                      │
            │                                      ▼
            │                                 SKILL.md
            │
            ├── ИИ выбрать навык ─────────────────→ registry.yaml
            │                                      │
            │                                      ▼
            │                                 SKILL.md
            │
            └── Конфликт / происхождение ─────────→ skill-boundaries.md / SOURCE.md
```

`SKILL.md` — источник истины для **выполнения**. `skills/registry.yaml` — валидируемый routing contract для **invocation, декларативных triggers, capability, references, связей и handoff**. `SKILLS.md` — каталог для человека. `capabilities/registry.yaml` — единственный переносимый vocabulary capability. Project-level `agents-devkits.yaml` объявляет выбранные skills и проверки проекта, но не заменяет инструкции проекта. Концептуальный документ — источник истины для **направления развития системы**. Инструкции проекта и явный запрос пользователя по-прежнему имеют приоритет над общими указаниями навыков.

# UX Writing

Use this skill for interface language, not product marketing pages or legal copy unless the project explicitly combines those concerns.

## Workflow

1. Identify the interface state, user intent, product voice, locale, character limits, and any established content guidelines.
2. Make actions specific and outcome-oriented. Explain errors as what happened, what it means, and the next useful action without blaming the user.
3. Give empty states a reason to exist and a clear next step. Preserve accessibility through visible labels, non-color-only instructions, and understandable status updates.
4. Avoid hidden string concatenation, unexplained jargon, placeholder-only labels, and irreversible confirmations with vague buttons such as “OK”.
5. Hand implementation to `design-code` and review visible behavior with `accessibility-review` when copy changes affect labels, announcements, or error recovery.

Read [copy-checklist.md](references/copy-checklist.md) for review criteria.

## Completion evidence

Return the final copy or redline, state/locale assumptions, character-limit checks performed, unresolved legal or product decisions, and risks for translation or accessibility.

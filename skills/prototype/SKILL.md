# Prototype

Use this skill to learn before building. It does not authorize user research, external communication, or production deployment.

## Workflow

1. State the question the prototype must answer and the decision it will inform.
2. Choose the lowest fidelity that can answer it: content outline, user flow, wireframe, interactive prototype, visual design, or code proof.
3. Include happy path, empty, loading, error, and recovery paths where they affect the decision.
4. Define validation tasks, success criteria, participants or stakeholders, and the evidence needed to proceed. Obtain explicit authorization before recruiting users or sharing artifacts externally.
5. Hand visual-system work to `apply-aesthetic` or `design-system`; production implementation to `feature-development` or `design-code`.

## Completion evidence

Return the artifact type, decision question, assumptions, validation plan, findings observed, and next action. Do not present an untested prototype as validated research.

# Apply Aesthetic

Use this skill when a product needs a deliberate visual character rather than a generic restyle. It owns the direction, not the implementation or the final visual QA.

## Workflow

1. Read the product brief, approved brand assets, existing design system, and supplied references. These outrank generic aesthetic preferences.
2. State the intended audience, product tone, dominant mood, hierarchy, density, and motion restraint before proposing changes.
3. Express the direction as reusable token roles and layout principles: type contrast, surface hierarchy, spacing rhythm, radius, elevation, and motion. Do not copy logos, photographs, proprietary typefaces, or brand copy from a reference.
4. Check that primary text, controls, focus indicators, and status colors can meet the project's accessibility target. A visual direction that depends on inaccessible contrast is not viable.
5. Hand implementation to `design-system`, `design-tokens`, or `design-code`; use `design-review` and `visual-qa` only after a rendered result exists.

## Completion evidence

Return the design decision, token-level implications, approved references used, constraints preserved, and risks that need an expert visual review. Do not claim visual fidelity without rendered evidence.

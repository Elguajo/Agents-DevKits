# Post-run learning and structural promotion

Use after a human correction, repeated workflow failure, predictable failure
despite following a skill, recurring wasted work, or a validation failure that
reveals a systemic gap. Do not add a reflection step to routine successful work.

Classify the lesson: **ONE-OFF** (no durable change), **RECURRING LOCAL**
(improve an existing skill, reference, validator, helper, or test), or
**SYSTEMIC** (improve a shared contract, policy, registry, or gate).

Prefer schema/type/contract, validator or gate, canonical helper, test/runtime
check, then prose where judgment is necessary. A new skill remains the last
option. For a behavioral improvement claim, preserve deterministic routing and
positive/negative scenarios and use a proportional live paired pilot before
promotion. Static contract success is not measured behavior improvement.

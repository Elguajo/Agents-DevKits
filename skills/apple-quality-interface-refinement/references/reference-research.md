# Reference Research

References answer how a mature product solves the same problem. They are not a
mood board and never a source of borrowed composition or branding.

## Precedence

1. an explicit user-provided reference or approved Figma;
2. the current product identity and existing design system;
3. production products solving the same user problem;
4. strong examples of the same interaction pattern;
5. Apple interfaces and HIG where relevant;
6. general design inspiration.

Higher precedence wins on conflict. A supplied reference outranks generic
Apple guidance; the existing design system outranks an admired third product.

## Extract from each reference

- the problem it is solving;
- its information hierarchy;
- its interaction model;
- its density and spacing logic;
- its component and state behavior;
- its motion and continuity behavior;
- what transfers to this product;
- what explicitly does not transfer, and why.

A reference with no "does not transfer" line has not been analyzed.

## Rules
- Use a few relevant references rather than many weak ones.
- Do not adopt a pattern because a famous product uses it.
- Do not reproduce protected assets, brand marks, illustration, or copy.
- When the current design already solves the problem clearly, no reference is needed.
- Concept and showcase work can inform visual direction but is not evidence of
  usable interaction.

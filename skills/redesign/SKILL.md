# Redesign

Use this skill when a working UI needs a deliberate quality upgrade. Preserve required behavior and approved content unless the user separately requests product changes.

## Workflow

1. Inspect the current implementation, known constraints, user flows, design system, and baseline screenshots or metrics where available.
2. Diagnose specific hierarchy, consistency, usability, accessibility, responsive, or performance problems before proposing a new direction.
3. Make the smallest coherent system-level changes: tokens and typography first, then components, layout, and motion. Avoid page-specific palettes and duplicate primitives.
4. Preserve functional behavior; route behavior changes to `product-spec` and `solution-architecture` when they alter product scope.
5. Verify the changed screens with `visual-qa`, `accessibility-review`, and relevant browser tests. Use `design-review` for independent expert assessment.

## Completion evidence

Return baseline findings, decisions made, artifacts changed, checks run, preserved constraints, and unresolved risks.
